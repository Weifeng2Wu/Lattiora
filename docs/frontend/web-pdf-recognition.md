# 浏览器 PDF 元数据识别

基准为 `b6320ce5` 的 `pdf_recognize.rs`。保留原 PDF 导入入口、文件名占位论文、异步识别、原后台任务面板以及手动元数据优先规则。

General 设置默认启用 Zotero 公共识别服务 `https://services.zotero.org/recognizer/recognize`，无需 API Key；支持自定义 URL、可选 Bearer API Key、测试连接和关闭识别。空地址恢复默认，已有自定义地址保留；旧配置有 Key 但缺少地址时不将 Key 自动转发到公共服务。Key 经现有 Worker 加密设置接口保存，浏览器持久化和文件同步仅保留掩码。测试连接真实提交一页公开 arXiv 编号并校验识别响应，不能只返回 HTTP 200 就宣布成功。

PDFium 在浏览器提取前五页文字/坐标，转换到 Zotero 识别 payload 的 PDF 左下角坐标系，保留行 → 文字分组 → 单词的嵌套层次；修正缺失分组层导致官方接口返回 500 的问题。发送内容包含标题文件名及这五页文字/坐标，不上传完整 PDF。请求上限 2 MiB，响应复用 4 MiB 有界读取、30 秒超时、禁止携带凭据重定向。当前使用 PDFium text span 作为识别词单元，字体样式不伪称具有原 liteparse 的完全一致精度。无可提取文字会报告错误，保留原文件；可使用已有 OCR/解析服务或手动编辑元数据。

识别结果中的 DOI/arXiv/ISBN 必须经现有精确 lookup 解析再应用；无标识符时使用标题/作者等结果。`.agentero/recognition/<uuid>.json` 保存任务状态、PDF SHA-256 和识别结果，随文件备份/同步，不保存请求文字或密钥。离线、关闭识别及缺少必要自定义地址时等待；启动、联网、配置变化和每 30 秒触发扫描。跨标签页使用 Web Lock，失败以 30/60 秒退避，三次后保留失败任务；永久解析错误立即失败。原任务面板可取消当前请求，General 可重新排队失败/取消任务。

自动写入同时验证元数据、笔记及 PDF 的本地版本，尊重 `meta_source=manual`。标题更新沿用原笔记 aliases/H1 保留逻辑；替换 PDF 或编辑元数据不会被在途结果覆盖。

## 目录归一与重复资料保留

精确识别标识符后使用原 arXiv stem / DOI 下划线目录名；已有目标不覆盖。重复论文按较早 added_at、再按路径选择稳定主记录，避免相互归档；保留主论文的标题/笔记，将新导入的整包 PDF、NOTES、source 和附件移动到主论文 `attachments/import-<uuid>`。原 `.paper.json` 改名为 `import-metadata.json` 留作来源记录，不生成第二条库记录。链接修复复用原移动管线，打开的论文标签切换到主记录，其他路径随移动重映射。

资料移动、链接修复、metadata 路径更新和任务完成状态在同一 IndexedDB 事务提交；版本变化、取消、同名文件冲突会整体回滚。未保存的笔记和源文件阻止移动，保存后可重试。同步任务先于论文到达时保持等待，不误标为跳过。

## 尚未完成的部分

- 云端仍按单文件 CAS 同步，其他设备可能暂时看到移动的中间状态；跨文件云端原子事务和批量冲突修复仍待实现。
- 跨设备同时执行同一任务时仍可能重复调用识别服务；文件同步会保留冲突，但没有服务器执行租约或外部 exactly-once 保证。
- 页面关闭后由下次打开恢复任务，并非后台持续运行；识别结果和应用完成之间发生崩溃可能重新请求。扫描 PDF 不自动额外收费调用 OCR。
