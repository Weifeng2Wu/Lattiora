# 网页 Wiki 标题重命名

保留原 Markdown 编辑器的右键「Rename current heading / 重命名当前标题」和原弹窗。只对已保存的 ATX 标题执行显式重命名；普通编辑/自动保存不会触发批量链接重写。前端提供保存文本快照、标题层级路径与行号，经 `wiki_rename_heading` 路由至浏览器实现。

迁移依据为官方基准 `b6320ce5` 的 `heading_rename.rs`、原前端 `heading-rename.ts` 和标题弹窗。实现复用原锚点提取规则，更新完整路径与可唯一定位的简写路径，保留自引用、嵌入、显示别名、Markdown 链接标题、CRLF、缩进和结尾 `#`。引用子标题时，如果引用省略了被改名的父标题，不改动该简写。

## 写入保护

- 按保存快照、行号与标题路径核对源标题；不匹配则要求重载。
- 原标题、新标题及重写后的链接都必须唯一解析；可能受影响的无效或歧义引用阻止操作。
- 对目标及入链来源检查未保存编辑；无关文件的未保存编辑不阻止操作。
- 逐片段修改原字符串，不重新序列化整份 Markdown；跳过 frontmatter、代码块与行内代码中的文本。
- 在 `files` Web Lock 下读取文件快照并制定计划；事务提交前再次核对文件版本与本地修改标识，防止计划覆盖期间到达的变动。
- 目标及全部来源在一个 IndexedDB 事务内提交。任何写入失败会整体中止，不留下半数本地文件更新。完成后通知原编辑器重载和嵌入刷新，文件进入既有 outbox/同步/ZIP 备份。

## 范围与限制

沿用原 ATX 标题规则，不把 Setext 标题或 PDF 标题冒充可重命名对象。隐藏目录不参与现有 Wiki 索引。标题中会破坏已存在引用语法的分隔符会被拒绝，不能成功提示后留下已破坏的链接。

本地原子性不等于云端多文件原子性：Worker 当前按单文件 CAS 同步。其他设备可在同步途中看到部分变化；同时编辑时保留冲突副本，但多文件冲突可能需要人工统一标题和来源链接。云端批量原子协议与冲突比较/合并 UI 仍列为欠项。本批不依赖外部模型或新增服务配置。

## 验证

`test/cloud-wiki-heading.test.ts` 移植原父子路径/简写/别名/自引用测试，并覆盖 CRLF、Unicode、代码/frontmatter、未保存内容、过期快照、歧义标题、写入故障原子回滚和规划期间的并发保存。原 `test/wiki-heading-rename.test.ts` 继续验证编辑器锚点规则。

浏览器场景位于 `test/browser/wiki-heading.spec.ts`，使用原文件导入、原编辑器右键与弹窗，检查离线修改目标及入链、离线重载和恢复同步。
