# 冲突副本管理

根目录 `Conflicts/` 是同步、恢复备份和编辑版本校验产生的恢复区。它不再显示在工作区文件树、Quick Open、正文搜索或 Wiki 候选中；普通路径（如 `notes/Conflicts/`）仍是用户文件夹。副本继续保存在浏览器与云端，并包含在完整备份中，不通过隐藏操作删除数据。

入口为「设置 → 同步 → 处理冲突」。选择原文件后，文本文件可比较各处差异，保留当前版本、使用另一个版本，或逐段选择后保存。二进制文件及大于 128 KiB 的文本提供两个版本的下载与整文件选择；超过一百万个行对的文本比较退化为整段差异，避免阻塞界面。

冲突列表中的「一键处理相同副本」按文件类型与逐字节内容比较（包括二进制），相同副本沿用原归档事务清理，工作区当前文件不改写。双方明确删除的冲突也可归档；缺失缓存、缺少原文件和空文件不视为删除。内容不同的项仍留在列表供选择，不按时间戳猜测新旧或自动合并。批次固定为点击时的快照，各项继续检查版本和未保存编辑；单项失败保留副本并通过 Toast 提示，其他项继续处理，完成后显示处理与剩余数量。

提交前检查原文件、冲突副本、说明文件的本地版本，以及打开编辑器的未保存状态。比较期间有新编辑则拒绝覆盖，重新打开比较后再处理。删除冲突与空文件有不同语义。两个版本和处理记录原子归档到 `.agentero/conflict-history/`，再清理已处理副本并修改原文件；归档也进入同步和完整 ZIP 备份。保留同批次中其他文件的冲突。

此功能是用户确认后的本地事务，沿用逐文件云端 CAS，不提供跨设备多文件原子提交。损坏的删除标记不会被解释为删除意图；有实际副本时仍允许从独立副本入口恢复。
